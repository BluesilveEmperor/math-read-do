## 0. 背景与目标

`math-read-do` 是单仓四长期分支的 AI Agent skill 系列：

| 分支 | 定位 | SKILL.md 行 | 专属工具 |
|------|------|------------|---------|
| main | 通用数学论文复现（基准版） | 531 | skills/（编排层） |
| routine | 跨语言栈例行复现 | 530 | skills/ |
| financial | 量化金融论文复现 | 507 | fin_tool/ |
| obj | 图形学3D网格简化复现 | 648 | qem_tool/ + corpus/ |

四分支共享 `_shared/` + 四大 `nature-*` 子技能（reader 80 / figure 305 / paper2ppt 83 / archify 127 行，**四分支字节级一致**）。

**目标**：建立四分支统一的可度量指标体系 + 评测框架，按 **效果 / 效率 / 工具性能 / 健壮性** 四维度逐项优化，使 skill 系列从"靠人工验收"升级为"可量化、可回归、可对比"。

## 2. 评测框架设计

### 2.1 现状缺口
- 仅 main/routine 有 `test-prompts.json`（6 例，同 blob），**无评分器/断言/rubric**——本质是人工验收清单
- financial/obj **无评测集**
- 全仓**无 grader 脚本**，效果无法 CI 化

### 2.2 框架设计

```
_shared/eval/                          # 评测框架（四分支共享，下沉到 _shared）
├── test-prompts.json                  # 统一评测集（扩展 + 领域用例）
├── grader.py                          # 评分器：按 assertions[] + rubric 机判
├── metrics_collector.py               # 指标采集（token/耗时/覆盖率）
└── report/                            # 指标 dashboard + 回归比对
```

**数据集**：统一 `test-prompts.json`，每例含：
```json
{
  "id": 1,
  "branch": "obj",
  "prompt": "...",
  "expected": "...",
  "assertions": [
    {"type": "file_exists", "path": "results/statistical_summary.json"},
    {"type": "json_field", "path": "...", "field": "verdict", "in": ["pass","approx"]},
    {"type": "exit_code", "eq": 0}
  ],
  "rubric": [{"item": "...", "weight": 1}],
  "domain": "...", "complexity": "..."
}
```

**评分器** `grader.py`：对每例跑 skill → 收集产物 → 逐条 `assertions` 布尔断言 → 按 `rubric` 加权打分 → 输出 `{case_id, passed, score, evidence}`。

**运行**：`python -m _shared.eval.grader --branch obj`，CI 集成（pytest + eval harness），回归比对历史指标。

**指标采集**：`metrics_collector.py` 采集首响 token（wc）、QEM 吞吐（benchmark）、覆盖率（pytest --cov）、跨分支一致性（diff），汇总到 `report/dashboard.json`。

### 2.3 落地策略
- 评测框架下沉到 `_shared/eval/`（四分支共享，避免四份漂移）
- 各分支 `test-prompts.json` 保留领域用例，共享通用用例
- 先在 obj 试点，验证后同步其余三分支

## 4. 优先级与实施路线图

### 4.1 优先级定义
- **P0**：阻断性/数据失真/性能不可接受 — 必须先做
- **P1**：显著提升可度量性/性能/健壮性 — 紧随
- **P2**：收敛一致性/工程卫生 — 批次
- **P3**：锦上添花


## 5. 风险与约束

| 风险 | 缓解 |
|------|------|
| 四分支 SKILL.md 同步成本高（门禁/枚举/路径统一） | 按 codedocs/08 worktree+cherry-pick 工作流；先 obj 试点再同步 |
